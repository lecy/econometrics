The anatomy of a template

Every R Markdown file is a plain text file that mixes three languages: YAML for settings, markdown for prose, and R for code. When you knit, R runs the code, drops the results into the text, and pandoc converts the whole thing into HTML, PDF, or Word.

A good template puts the same pieces in the same order every time, so you never start from a blank page.

Here is the same skeleton as plain text. The starter template is a complete version you can knit right away.

---
title: "My Report"
output: html_document
---

```{r setup, include=FALSE}
knitr::opts_chunk$set( echo=TRUE, message=FALSE, warning=FALSE )
```

```{r packages}
library( dplyr )
source( "utils.R" )
```

```{r data}
dat <- read.csv( "data/my-data.csv" )
```

## Results

Prose in markdown, with math like $y = \beta_0 + \beta_1 x$.

```{r model}
m <- lm( y ~ x, data=dat )
summary( m )
```

```{css, echo=FALSE}
h1 { color: #bd5416; }
```

The basics

YAML headers and document types

The YAML header sits between two lines of three dashes at the very top of the file. It holds the document’s metadata (title, author, date) and, most importantly, the output format. Indentation matters: nested options are indented two spaces under their parent.

---
title: "Program Evaluation Report"
author: "Your Name"
date: "2026-09-30"
output:
  html_document:
    toc: true            # table of contents
    toc_float: true      # keep it visible while scrolling
    code_folding: hide   # let readers show or hide code
---

Swap html_document for pdf_document or word_document to change the output type (see HTML, PDF, or Word). Quarto files (.qmd) use the same idea but call the field format: instead of output:.

Learn more: HTML document options · Quarto HTML options

Loading packages and sourcing custom code

Load every package in one chunk near the top, so a reader can see all of the document’s dependencies at a glance.

  • Install packages in the console, not in the document. An install.packages() call inside an RMD file reinstalls the package every time you knit.
  • Use source() for your own functions. Keep helper functions in a separate .R file and pull them in with one line. source() also works with a URL, which makes it easy to share code across projects.
library( dplyr )
library( stargazer )

source( "R/helper-functions.R" )                                   # local file
source( "https://raw.githubusercontent.com/user/repo/main/utils.R" ) # on the web

Learn more: Packages chapter of R for Data Science · Sourcing code in the Cookbook

Loading data: local files versus URLs

When you knit, R sets the working directory to the folder that holds the RMD file. Local paths are read relative to that folder, so a data file in a data subfolder is simply "data/my-data.csv". Avoid setwd() and full paths like C:/Users/...: they break as soon as the file moves to another computer.

Data stored online can be read straight from a URL. On GitHub, click Raw to get the address of the file itself rather than the web page around it.

dat <- read.csv( "data/my-data.csv" )                                  # local
dat <- read.csv( "https://raw.githubusercontent.com/user/repo/main/data.csv" ) # URL
dat <- readRDS( gzcon( url( "https://example.com/data.rds" ) ) )       # .rds from a URL

For large downloads, add cache=TRUE to the chunk so the file is fetched once instead of on every knit.

Markdown rules

Markdown is a set of light formatting conventions for plain text. A handful of rules cover almost everything you will write:

You type You get
# Heading / ## Subheading section headings
**bold** and *italic* bold and italic
* item or 1. item bulleted or numbered lists
[link text](https://...) a hyperlink
`code` inline code
> quote an indented call-out block
a blank line a new paragraph

You can also drop R results into a sentence with inline code: typing `r nrow(dat)` prints the number of rows, so the text updates whenever the data changes.

Learn more: Markdown overview (DS4PS textbook) · Pandoc’s Markdown in the Definitive Guide

Code chunk arguments and global settings

A code chunk opens with ```{r} and closes with ```. Inside the braces you can add a label (a short name, which helps with debugging and file names for figures) and options that control what shows up in the output.

```{r model-results, echo=FALSE, fig.width=8}
plot( dat$x, dat$y )
```

The options you will use most:

Option What it does
echo=FALSE runs the code but hides it; only results appear
eval=FALSE shows the code but does not run it
include=FALSE runs the code, shows nothing (good for setup)
message=FALSE, warning=FALSE hide package messages and warnings
results="asis" passes output through as raw markdown or HTML
fig.width, fig.height figure size in inches
fig.cap figure caption
cache=TRUE save results and skip re-running slow chunks

Set defaults for the whole document once, in the setup chunk, with knitr::opts_chunk$set(). Any option written on an individual chunk overrides the default. In Quarto, options move inside the chunk as special comments: #| echo: false.

Learn more: Complete list of chunk options (Yihui Xie) · Chunk options in the Cookbook

Mathematical formulas

R Markdown understands LaTeX math. Wrap an expression in single dollar signs for inline math, like $\bar{x}$, or double dollar signs for an equation on its own line:

$$
Y_i = \beta_0 + \beta_1 X_i + \epsilon_i
$$

\[ Y_i = \beta_0 + \beta_1 X_i + \epsilon_i \]

Greek letters (\alpha, \beta), hats (\hat{\beta}), subscripts (x_i), superscripts (x^2), and fractions (\frac{a}{b}) cover most of what you need for regression models.

Learn more: Math in R Markdown (R. Pruim) · LaTeX mathematics (Wikibooks)

Embedding images, image options, and captions

There are two ways to add an image that is not produced by R code:

![Caption text shown under the image](images/logic-model.png){width=60%}
```{r, echo=FALSE, out.width="60%", fig.align="center", fig.cap="Caption text"}
knitr::include_graphics( "images/logic-model.png" )
```

The markdown version is quickest. The chunk version gives you the full set of figure options, and it treats pictures and R plots the same way. For plots made in R, remember the difference between two sizes: fig.width and fig.height set the size R draws the plot at (which controls text size), while out.width sets how large it is displayed on the page.

Learn more: Figures in the Cookbook · Figure options in Quarto

Citation management

Citations need two things in the YAML header: a bibliography file (BibTeX, .bib) and, optionally, a citation style file (.csl). Cite a source with its key, and pandoc formats the citation and adds the reference list at the end of the document.

bibliography: references.bib
csl: apa.csl
Class size effects fade over time [@finn1990]. As @krueger1999 shows, ...

You do not have to build the .bib file by hand. The RStudio visual editor can insert citations from Zotero, a DOI, or a search, and it adds them to your bibliography automatically. Thousands of journal styles are available as .csl files.

Learn more: Bibliographies in the Cookbook · Citations in the RStudio visual editor · Zotero style repository

Style and output

Syntax highlighting styles

The highlight option in the YAML header controls the colors used for code. Built-in choices include default, tango, pygments, kate, monochrome, espresso, zenburn, haddock, breezedark, and textmate.

output:
  html_document:
    highlight: tango

In Quarto the option is highlight-style: and it accepts many more themes (for example github or atom-one).

Learn more: Pandoc syntax highlighting examples (Garrick Aden-Buie) · Quarto code highlighting

R-to-HTML functions and results="asis"

By default, knitr treats printed output as plain text and places it in a gray output box. Many packages instead write formatted markdown or HTML for you: pander(), knitr::kable(), stargazer( type="html" ), and kableExtra. Some return output that knitr already knows how to display; others (such as stargazer) print raw HTML and need the chunk option results="asis" so it is passed through untouched.

The same trick lets you write text with code. The chunk below uses cat() to build a markdown list, and results="asis" turns it into a real list:

for( v in c("mpg","hp","wt") )
{
  cat( "* Mean of **", v, "**: ", round( mean( mtcars[[v]] ), 1 ), "\n", sep="" )
}
  • Mean of mpg: 20.1
  • Mean of hp: 146.7
  • Mean of wt: 3.2

Learn more: results=“asis” in the Cookbook · kableExtra for HTML tables · stargazer cheatsheet

Custom style sheets: embedded versus imported

HTML output is styled with CSS, so you can change fonts, colors, and spacing. There are two ways to add your own rules.

  • Embedded: a css chunk inside the document. The rules travel with the file, which is handy for a few quick changes. Use echo=FALSE so the CSS does not print.
  • Imported: a separate .css file named in the YAML header. One file can style a whole collection of documents, and a change in one place updates all of them.
```{css, echo=FALSE}
h1, h2 { color: #153243; }
p { max-width: 45em; }
```
output:
  html_document:
    css: styles.css

This page uses both: an imported style sheet shared by the course lecture notes, plus an embedded chunk at the bottom of the file that styles the anatomy diagram. CSS only affects HTML output; it has no effect on PDF or Word documents.

Learn more: HTML and CSS in the Cookbook · CSS basics (MDN)

Formats and templates

HTML, PDF, or Word

The same RMD file can produce several document types, but they are not equally forgiving. HTML is the most stable choice: everything in this guide works there, it needs no extra software, and it is the format we use for labs.

HTML PDF Word
Extra software none LaTeX (tinytex) Word or LibreOffice
Custom CSS yes no no
HTML tables (stargazer, kableExtra HTML) yes no, use LaTeX versions no
Interactive widgets yes no no
Styling CSS LaTeX templates a reference .docx
  • PDF output runs through LaTeX. Install it once with tinytex::install_tinytex(). Code that prints HTML will fail or disappear.
  • Word output is useful when collaborators need track changes. Style it by supplying a reference document whose styles you have edited (reference_docx:).

Learn more: PDF documents · TinyTeX · Styling Word output

Advanced document types

Beyond reports, R Markdown can produce slides, dashboards, and more. Each is a different output: value, and most come from an add-on package.

  • PowerPoint (powerpoint_presentation): editable slides, styled with a reference .pptx.
  • HTML slides: ioslides_presentation and slidy_presentation are built in; xaringan and Quarto’s revealjs are more flexible.
  • Dashboards (flexdashboard): arrange charts, tables, and value boxes in rows and columns.
  • Storyboards (a flexdashboard layout): a sequence of frames, each with a chart and commentary, for walking a reader through an analysis.
  • Books and websites (bookdown, distill, Quarto projects): many files knit into one connected site.

Learn more: PowerPoint presentations · flexdashboard · Storyboards · Quarto presentations

The R Markdown template gallery

You do not need to design a template from scratch. The format gallery shows dozens of ready-made output types, and several packages add polished HTML themes: rmdformats, prettydoc, and tufte are good places to start. After installing one, its templates appear in RStudio under File > New File > R Markdown > From Template.

Learn more: R Markdown formats gallery · rmdformats · prettydoc · tufte

Quarto academic journal templates

Quarto is the next generation of R Markdown. A .qmd file looks almost the same as an .rmd file, and Quarto can also knit Python and Julia. Its main advantage for research is a set of journal templates that format a manuscript to a publisher’s specifications (Elsevier, PLOS, the American Chemical Society, the Journal of Statistical Software, and others). Start a new paper from a template with one command in the terminal:

quarto use template quarto-journals/elsevier

The rticles package offers the same service for .rmd files.
